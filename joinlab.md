```sql
    return_date TEXT,
    FOREIGN KEY (book_id)   REFERENCES books(book_id),
    FOREIGN KEY (reader_id) REFERENCES readers(reader_id)
);
```

## 2. Теоретическая часть

### 2.1. Зачем нужны JOIN

В реляционной базе данные хранятся в нескольких связанных таблицах, чтобы избежать дублирования. Название книги хранится в `books`, а имя её автора — в `authors`. Чтобы получить «книга + её автор», нужно **объединить** две таблицы по общему полю — внешнему ключу (`author_id`).

**JOIN** — операция, которая сопоставляет строки одной таблицы со строками другой по заданному условию и формирует результат.

### 2.2. Как это работает

Допустим, есть таблица `authors`:

| author_id | last_name |
|-----------|-----------|
| 1         | Толстой   |
| 2         | Оруэлл    |
| 3         | Азимов    |

И таблица `books`:

| book_id | title         | author_id |
|---------|---------------|-----------|
| 10      | Анна Каренина | 1         |
| 11      | 1984          | 2         |
| 12      | Война и мир   | 1         |
| 13      | Книга без автора | NULL   |

**`INNER JOIN`** берёт каждую строку из левой таблицы, ищет подходящую строку в правой по условию `authors.author_id = books.author_id`. Если находит — пара попадает в результат. Если нет — строка отбрасывается.

Результат `authors INNER JOIN books`:

| author_id | last_name | book_id | title         |
|-----------|-----------|---------|---------------|
| 1         | Толстой   | 10      | Анна Каренина |
| 1         | Толстой   | 12      | Война и мир   |
| 2         | Оруэлл    | 11      | 1984          |

Автор №3 и книга №13 **не попали** в результат — для них нет пары.

**`LEFT JOIN`** берёт **все** строки из левой таблицы. Если пары в правой нет — поля правой заполняются `NULL`.

Результат `authors LEFT JOIN books`:

| author_id | last_name | book_id | title         |
|-----------|-----------|---------|---------------|
| 1         | Толстой   | 10      | Анна Каренина |
| 1         | Толстой   | 12      | Война и мир   |
| 2         | Оруэлл    | 11      | 1984          |
| 3         | Азимов    | NULL    | NULL          |

### 2.3. Виды соединений

| Вид | Что возвращает |
|-----|----------------|
| `INNER JOIN` | Только строки, для которых есть пара в обеих таблицах |
| `LEFT JOIN` | Все строки левой таблицы + совпадения из правой (или NULL) |
| `CROSS JOIN` | Декартово произведение (каждая с каждой) |

### 2.4. Синтаксис

```sql
SELECT столбцы
FROM левая_таблица
[INNER | LEFT | CROSS] JOIN правая_таблица
    ON условие_соединения
WHERE фильтр
ORDER BY сортировка;
```

- `ON` задаёт **условие соединения** (обычно равенство внешнего ключа и первичного ключа).
- `WHERE` фильтрует результат **после** соединения.
- Алиасы (`a`, `b`) делают запрос короче: `FROM authors AS a JOIN books AS b ON a.author_id = b.author_id`.

### 2.5. Типичные ошибки

1. **Условие соединения в `WHERE` для `LEFT JOIN`.**  
   `... LEFT JOIN books ON ... WHERE books.genre = 'Роман'` превращает `LEFT JOIN` в `INNER JOIN` — все строки с `NULL` в `genre` отбрасываются.

2. **Забытый `ON` → `CROSS JOIN`.**  
   Получите декартово произведение, часто огромное.

3. **Неоднозначные имена столбцов.**  
   Если `author_id` есть в обеих таблицах — указывайте `authors.author_id` или используйте алиасы.

4. **Размножение строк.**  
   Одной строке левой таблицы может соответствовать несколько строк правой — это нормально, но влияет на агрегаты.

## 3. Пошаговые примеры с объяснением

### Пример 1. `INNER JOIN`: книга + автор

```sql
SELECT b.title, a.first_name, a.last_name
FROM books AS b
INNER JOIN authors AS a ON b.author_id = a.author_id
ORDER BY b.title;
```

**Что произойдёт:** для каждой книги ищется строка автора с тем же `author_id`. Книга без автора (`author_id = NULL`) не попадёт — `NULL = NULL` в SQL не истинно.

**Результат:** 10 строк.

### Пример 2. `LEFT JOIN`: сохранить все книги

```sql
SELECT b.title, a.last_name AS author
FROM books AS b
LEFT JOIN authors AS a ON b.author_id = a.author_id
ORDER BY b.title;
```

**Что изменилось:** теперь в результат попадут **все** книги, включая «Книгу без автора». Для неё `author` будет `NULL`.

**Результат:** 11 строк.

### Пример 3. Три таблицы

```sql
SELECT r.last_name AS reader, b.title, a.last_name AS author,
       l.loan_date, l.return_date
FROM loans AS l
JOIN readers AS r ON l.reader_id = r.reader_id
JOIN books   AS b ON l.book_id   = b.book_id
LEFT JOIN authors AS a ON b.author_id = a.author_id
ORDER BY l.loan_date;
```

Начинаем с `loans`, присоединяем `readers` и `books` через `INNER JOIN` (связи обязательные), а `authors` — через `LEFT JOIN`, потому что книга может быть без автора.

### Пример 4. Агрегация после JOIN

Количество выдач по каждому читателю (включая тех, кто ничего не брал):

```sql
SELECT r.last_name AS reader, COUNT(l.loan_id) AS loans_count
FROM readers AS r
LEFT JOIN loans AS l ON r.reader_id = l.reader_id
GROUP BY r.reader_id, r.last_name
ORDER BY loans_count DESC;
```

> Важно: используем `COUNT(l.loan_id)`, а не `COUNT(*)`. `COUNT(*)` посчитает и строки с `NULL`, дав 0-строчным читателям значение 1.

### Пример 5. Поиск «сирот» через `LEFT JOIN … WHERE … IS NULL`

Найдём книги, которые ни разу не выдавались:

```sql
SELECT b.title
FROM books AS b
LEFT JOIN loans AS l ON b.book_id = l.book_id
WHERE l.loan_id IS NULL;
```

`LEFT JOIN` оставляет все книги; для невыданных поля из `loans` равны `NULL`. Условие `WHERE l.loan_id IS NULL` отбирает именно такие строки.

### Пример 6. `CROSS JOIN`

```sql
SELECT a.last_name AS author, r.last_name AS reader
FROM authors AS a
CROSS JOIN readers AS r
ORDER BY a.last_name, r.last_name;
```

6 авторов × 5 читателей = 30 строк — все возможные пары.

## 7. Шпаргалка

```sql
-- INNER: только совпадения
SELECT * FROM A JOIN B ON A.key = B.key;

-- LEFT: все строки A + совпадения из B
SELECT * FROM A LEFT JOIN B ON A.key = B.key;

-- Поиск «сирот» в A (нет пары в B)
SELECT * FROM A LEFT JOIN B ON A.key = B.key
WHERE B.key IS NULL;

-- Три таблицы
SELECT * FROM A
JOIN B ON A.key = B.key
JOIN C ON B.key2 = C.key2;

-- Агрегация с LEFT JOIN
SELECT A.id, COUNT(B.id)
FROM A LEFT JOIN B ON A.id = B.a_id
GROUP BY A.id;
```
