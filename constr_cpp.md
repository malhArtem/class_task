# Конструкторы и деструкторы — порциями: теория → сразу практика

## Блок 1. Что такое конструктор (подробно)

### С чего всё начинается: объект и его поля

Когда ты пишешь класс, ты описываешь, **из чего состоит** объект:

```cpp
class Point {
public:
    int x;
    int y;
};
```

Класс — это чертёж. Объект — конкретная вещь, сделанная по чертежу:

```cpp
Point p;   // сделали объект p
```

Теперь важный вопрос: **а что лежит в полях `x` и `y` прямо после создания?**

Ответ неприятный: **мусор**. Там окажутся случайные числа, которые остались в памяти от прошлых программ. Это не «ноль по умолчанию» — это именно случайные значения.

```cpp
Point p;
std::cout << p.x;   // может напечатать 32767, -2147483648 или что угодно
```

С таким объектом работать нельзя: непонятно, что внутри. Значит, объект нужно **сразу привести в понятное состояние** — заполнить поля нормальными значениями. Раньше это делали руками после создания:

```cpp
Point p;
p.x = 0;
p.y = 0;
```

Но это легко забыть, и это неудобно. Именно для этого придумали **конструкторы**.

### Что делает конструктор

**Конструктор** — специальная функция, которая **автоматически вызывается в момент создания объекта**. Твоя задача — написать в ней, какие значения должны получить поля. Всё остальное компилятор сделает сам.

```cpp
class Point {
public:
    int x;
    int y;

    Point(int a, int b) {   // конструктор
        x = a;
        y = b;
    }
};

Point p(3, 5);   // создался объект — конструктор сам заполнил x=3, y=5
```

Разберём по шагам, что произошло в строке `Point p(3, 5);`:

1. Компилятор **выделил память** под объект `p`.
2. Увидел, что указаны аргументы `3` и `5`.
3. **Нашёл подходящий конструктор** — тот, что принимает два `int`.
4. **Вызвал его**, передав `3` и `5`. Внутри `x = 3, y = 5`.
5. Только после этого объект считается «готовым к использованию».

Теперь при создании объекта **нельзя забыть** его заполнить — конструктор сработает сам.

### Правила, которые надо запомнить сразу

1. **Имя конструктора совпадает с именем класса** — `Point()` для класса `Point`.
2. **У конструктора нет возвращаемого типа** — не `void`, не `int`, вообще ничего. Просто `Point(...)`.
3. **Вызывается автоматически** — руками его не зовёшь. Ты пишешь `Point p(3, 5);`, а компилятор сам понимает, что надо вызвать конструктор.
4. **Может быть несколько конструкторов** (с разными параметрами) — компилятор выберет подходящий по аргументам. Это называется **перегрузка**.

### Маленький пример целиком

```cpp
#include <iostream>

class Point {
public:
    int x;
    int y;

    Point(int a, int b) {
        x = a;
        y = b;
        std::cout << "Создана точка (" << x << ", " << y << ")\n";
    }
};

int main() {
    Point a(3, 5);
    Point b(-1, 0);
}
```

Вывод:

```
Создана точка (3, 5)
Создана точка (-1, 0)
```

Конструктор сработал дважды — по разу на каждый объект. Никаких ручных вызовов не было.

### Типичные ошибки новичков

- **Написать `void Point(int a, int b)`** — так нельзя, у конструктора нет возвращаемого типа.
- **Пытаться вызвать руками:** `p.Point(3, 5);` после создания — это не создаст точку заново, это просто ошибка (или вызов обычного метода, если такой есть).
- **Забыть, что конструктор — это не «инициализация по требованию».** Он работает **всегда** при создании. Если написал конструктор — он сработает, хочешь ты того или нет.

## Блок 2. Конструктор по умолчанию

Ты уже видел, что при создании `Point p(3, 5);` вызывается конструктор **с двумя аргументами**. А что если создать объект **без аргументов**?

```cpp
Point p;   // а тут какой конструктор вызовется?
```

Тут нужен **конструктор по умолчанию** — тот, который **не принимает аргументов**:

```cpp
class Point {
public:
    int x;
    int y;

    Point() { x = 0; y = 0; }              // по умолчанию
    Point(int a, int b) { x = a; y = b; }  // с параметрами
};

Point a;          // вызовется Point()
Point b(3, 5);    // вызовется Point(int, int)
```

Компилятор смотрит на аргументы и выбирает подходящий конструктор. Без аргументов — `Point()`. С двумя `int` — `Point(int, int)`.

### ⚠️ Важная ловушка

Если ты **написал хотя бы один конструктор** (любой, хоть с параметрами), компилятор **перестаёт автоматически создавать конструктор по умолчанию**. То есть такой код:

```cpp
class Point {
public:
    int x, y;
    Point(int a, int b) { x = a; y = b; }   // только один конструктор
};

Point p;   // ❌ ошибка компиляции: нет конструктора без аргументов
```

не соберётся. Компилятор как бы говорит: «Ты сам решил управлять созданием объекта — вот и разбирайся со всеми вариантами».

Отсюда правило: **если нужен конструктор по умолчанию — напиши его явно.**

## Блок 3. Что такое деструктор

Теперь про **обратную сторону**: объект ведь когда-то заканчивает своё существование. Это происходит, когда:

- переменная выходит из блока `{}`;
- заканчивается `main`;
- объект, созданный через `new`, удаляется через `delete`.

В этот момент автоматически вызывается **деструктор**.

```cpp
class Point {
public:
    Point()  { std::cout << "создан\n"; }
    ~Point() { std::cout << "удалён\n"; }
};
```

**Правила:**
- Имя — `~` + имя класса (`~Point`).
- Параметров и возвращаемого типа нет.
- Вызывается **автоматически**, как и конструктор.

**Зачем он нужен?** Пока объект «простой» (только числа) — он не нужен. Но если объект **захватил ресурс** (память, файл, соединение) — деструктор **обязан** его вернуть. Об этом — блок 4.

## Блок 4. Деструктор освобождает память

Если объект **сам выделяет память через `new`** — деструктор **обязан** её освободить.

```cpp
class IntArray {
    int* data;
    int  size;
public:
    IntArray(int n) {
        size = n;
        data = new int[n];       // взяли память
        for (int i = 0; i < n; i++) data[i] = 0;
    }
    ~IntArray() {
        delete[] data;           // вернули память
    }
    void set(int i, int v) { data[i] = v; }
    int  get(int i) const  { return data[i]; }
};
```

Здесь пара «конструктор ↔ деструктор» работает как единое целое: конструктор **взял** память, деструктор её **вернул**. Если забыть `delete[]` — **утечка памяти**: программа съест память и не отдаст.

## Блок 5. Счётчик живых объектов

Иногда хочется видеть, сколько объектов сейчас существует. Для этого — `static`-поле (одно на весь класс, общее для всех объектов).

```cpp
class Counter {
    static int count;   // общее для всех объектов
public:
    Counter()  { count++; }
    ~Counter() { count--; }
    static int get() { return count; }
};
int Counter::count = 0;  // обязательно определить снаружи
```

## Блок 6. Проблема копирования (задел на будущее)

Если у класса есть «сырой» указатель и ты пишешь `IntArray b = a;`, компилятор делает **поверхностную копию**: оба объекта смотрят на одну и ту же память. Потом оба деструктора делают `delete[]` — и программа падает.

Пока это **просто запомни как правило**: класс с `new` в конструкторе нельзя просто копировать. На следующем занятии мы это починим (конструктор копирования).
