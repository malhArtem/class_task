2. **Можно** запускать запросы на реальной СУБД (рекомендуется).

5. Сдавай работу в виде файла: **номер задания → запрос → (если нужно) ответ/вывод**.

7. В Части 1 **сначала пиши ответ на бумаге**, потом проверяй запуском. Иначе теряется весь смысл задания.

# Часть 4. `WITH` (CTE) (4 задания, 10 баллов)

> **Зачем нужен `WITH`?**
> Если запрос становится сложным (агрегация внутри агрегации, несколько уровней фильтрации), вложенные подзапросы делаются нечитаемыми. `WITH` позволяет разбить задачу на шаги и дать каждому шагу имя — как будто ты пишешь маленькие «временные таблицы».
>
> ```sql
> WITH имя_CTE AS (
>     SELECT ...
> )
> SELECT * FROM имя_CTE WHERE ...;
> ```

**Задание 16.** Найди все заказы, чья цена выше средней цены по всей сети. Сделай это через `WITH`.

# 🧭 Подсказка: что где искать

| Если задача про… | Вспомни про… |
|---|---|
| Пустые значения | `IS NULL` / `IS NOT NULL` |
| Несколько условий | `AND`, `OR`, `IN`, `BETWEEN` |
| Поиск по тексту | `LIKE` с `%` и `_` |
| Сортировку | `ORDER BY ... ASC/DESC` |
| Топ-N | `ORDER BY ... LIMIT N` |
| Подсчёты | `COUNT`, `SUM`, `AVG`, `MIN`, `MAX` |
| Группировку | `GROUP BY` + `HAVING` |
| Промежуточный результат | `WITH` |
| Изменение строк | `UPDATE ... SET ... WHERE ...` |
| Удаление строк | `DELETE FROM ... WHERE ...` |
| Добавление строк | `INSERT INTO ... VALUES (...)` |

### ⚠️ Отдельно про `NULL`

Помни три правила:

1. `NULL` — это **не** `0` и **не** пустая строка. Это «значение неизвестно».
2. Любое сравнение с `NULL` через `=`, `!=`, `<`, `>` возвращает **не TRUE и не FALSE**, а «неизвестно». Поэтому нужен `IS NULL` / `IS NOT NULL`.
3. Агрегатные функции (`SUM`, `AVG`, `COUNT(col)`) **игнорируют** `NULL`. А `COUNT(*)` — **не игнорирует**, он считает строки.

### ⚠️ Про `ORDER BY` и `LIMIT`

Если у нескольких строк одинаковое значение в сортировке — их порядок **не гарантирован**. `LIMIT 3` вернёт 3 строки, но какие именно — может меняться от запуска к запуску. Если нужна стабильность — добавляй второй ключ сортировки.
