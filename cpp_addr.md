# Указатели и ссылки в C++ — шаг → подробное объяснение → задание

## Часть I. Как устроена память

### Шаг 1. Переменная — это имя для ячейки памяти

Представьте, что память компьютера — это огромный шкаф с пронумерованными ящиками. Каждый ящик имеет **адрес** (номер) и хранит какое-то значение. Когда вы пишете:

```cpp
int x = 42;
```

происходит три вещи:

1. Компилятор решает, сколько памяти нужно под `int` (обычно 4 байта).
2. Находит свободное место — например, ящик с адресом `0x7ffd1234`.
3. Кладёт туда значение `42` и запоминает, что имя `x` соответствует этому адресу.

Дальше в программе вы пишете `x`, а компилятор подставляет «ящик по адресу `0x7ffd1234`». **Имя переменной — это просто удобный псевдоним адреса**, чтобы вам не приходилось вручную помнить числа.

Почему это важно понять сразу? Потому что указатели и ссылки — это два разных способа **работать с адресами напрямую**, а не через имя. Пока вы не чувствуете, что «за именем стоит адрес», указатели кажутся магией.

**📝 Задание 1.1.**
Объявите `int x = 42;` и выведите через `std::cout` три вещи: `x`, `sizeof(x)` и `sizeof(&x)`. Затем объясните своими словами: почему `sizeof(&x)` не равно `sizeof(x)`, и что вообще означает `&x`.

**Разбор.** `x` выведет `42`. `sizeof(x)` = 4 — столько байт занимает сам `int`. `sizeof(&x)` = 8 — столько байт занимает **адрес** (на 64-битной системе указатель всегда 8 байт). `&x` — это «взять адрес переменной `x`», то есть число-номер ящика. Размеры разные, потому что это разные сущности: значение (`int`) и адрес (`int*`).

### Шаг 2. Оператор `&` — «взять адрес»

Символ `&` перед уже существующей переменной означает **«дай мне адрес этого объекта»**. Результат — указатель.

```cpp
int x = 42;
std::cout << &x;   // например, 0x7ffd1234
```

Здесь легко запутаться, потому что `&` в C++ означает **три разные вещи** в зависимости от контекста:

- `&x` (перед переменной) — «взять адрес».
- `int& r` (в объявлении типа) — «ссылка».
- `a & b` (между двумя значениями) — побитовое И.

Компилятор различает их по контексту, а вам нужно различать по смыслу. Если видите `&` слева от имени при объявлении — это ссылка. Если `&` перед уже существующей переменной в выражении — это взятие адреса. Если между двумя выражениями — арифметика.

**📝 Задание 2.1.**
Объявите `int a = 1; int b = 2;`. Выведите `&a` и `&b`. Совпадают ли адреса? А если поменять порядок объявления? Объясните, почему адреса обычно отличаются на 4 (размер `int`), но полагаться на конкретные значения нельзя.

**Разбор.** Адреса разные, потому что это разные ящики. Они часто стоят рядом в стеке (разница 4 байта), но порядок и точные значения зависят от компилятора, оптимизаций и платформы. **Никогда не полагайтесь на конкретные адреса** — это неопределённое поведение с точки зрения стандарта.

---

### Шаг 3. Указатель — переменная, хранящая адрес

**Указатель** — это обычная переменная, только хранит она не число, а **адрес другого объекта**.

```cpp
int x = 42;
int* p = &x;   // p хранит адрес x
```

В памяти это выглядит так:

```
x:  [    42    ]   адрес 0x1000
p:  [ 0x1000   ]   адрес 0x2000
```

Обратите внимание: `p` — это **не** `42`. Это «записка с адресом, где лежит `42`». Если вы измените `x`, значение `*p` изменится тоже (потому что `*p` — это и есть `x`). Но если вы измените `p` (перенаправите на другой адрес), `x` не пострадает.

Тип указателя (`int*`, `double*`, `char*`) важен не для хранения адреса (адрес всегда 8 байт), а для того, чтобы компилятор знал, **сколько байт читать** при разыменовании и **на сколько сдвигать** при арифметике.

**📝 Задание 3.1.**
Объявите `int x = 10; int* p = &x;`. Выведите четыре вещи: `p`, `&p`, `*p`, `&x`. Сравните `p` и `&x` — что заметили? Сравните `&p` и `p` — почему они разные?

**Разбор.** `&x` — адрес переменной `x`. `p` хранит именно этот адрес, поэтому `p == &x`. А `&p` — это адрес **самого указателя** `p` (того ящика, где лежит «записка»). Это другой адрес, потому что `p` — отдельная переменная. `*p` = 10 — значение по адресу, то есть сам `x`.

---

### Шаг 4. Оператор `*` — разыменование

`*p` означает **«сходи по адресу `p` и возьми значение»**. Это работает и на чтение, и на запись:

```cpp
int x = 42;
int* p = &x;
std::cout << *p;   // 42 — читаем
*p = 100;          // записываем: x теперь 100
std::cout << x;    // 100
```

Символ `*` тоже перегружен смыслами, как и `&`:

- `int* p` (в объявлении типа) — «указатель на int».
- `*p` (перед переменной) — «разыменовать».
- `a * b` (между выражениями) — умножение.

Ключевой момент: `*p` и `x` — это **один и тот же объект**, просто два разных способа к нему обратиться. Меняя один, меняете другой. Это не копия — это буквально тот же ящик в памяти.

**📝 Задание 4.1.**
Дан код:
```cpp
int x = 10;
int* p = &x;
*p = 20;
std::cout << x << " " << *p << "\n";
```
Что выведет? Объясните, почему `x` и `*p` — это одно и то же, и что было бы, если бы `p` указывал на копию.

**Разбор.** Выведет `20 20`. `*p` — это «значение по адресу `p`», а `p` хранит адрес `x`, значит `*p` — это ровно `x`. Меняя `*p`, вы меняете `x`. Если бы `p` указывал на **копию** `x` (например, вы бы написали `int y = x; int* p = &y;`), то изменение `*p` поменяло бы `y`, а `x` осталось бы 10.

### Шаг 5. Размер указателя не зависит от типа

Указатель на `char` и указатель на `double` занимают **одинаковое** количество памяти — потому что оба хранят адрес, а адрес в системе один и тот же по размеру.

```cpp
std::cout << sizeof(int*);     // 8
std::cout << sizeof(char*);    // 8
std::cout << sizeof(double*);  // 8
```

Но тип нужен, чтобы компилятор знал, **как интерпретировать** байты по адресу. `char*` прочитает 1 байт, `int*` — 4, `double*` — 8. И при арифметике `p + 1` сдвиг будет на `sizeof(T)`, а не на 1 байт.

**📝 Задание 5.1.**
Выведите `sizeof(int*)`, `sizeof(char*)`, `sizeof(double*)`. Затем `sizeof(*p)` для каждого типа (нужно создать переменные). Сравните результаты и объясните разницу между размером указателя и размером объекта, на который он указывает.

**Разбор.** Все указатели по 8 байт. `sizeof(*p)` даст 4, 1 и 8 соответственно — это размеры **объектов**, на которые указывают указатели. Указатель всегда «одного размера» (адрес), но «знает», объект какого размера лежит по этому адресу.

### Шаг 6. `nullptr` — указатель в никуда

Указатель может не указывать ни на что. Для этого есть специальное значение **`nullptr`** (введено в C++11, до него писали `NULL` или `0`).

```cpp
int* p = nullptr;   // ни на что не указывает
```

Разыменовывать `nullptr` **нельзя** — это неопределённое поведение (UB), на практике обычно segfault:

```cpp
int* p = nullptr;
*p = 5;   // ❌ программа упадёт
```

Но **проверять** на `nullptr` можно и нужно, если не уверены, что указатель валиден:

```cpp
if (p != nullptr) {
    std::cout << *p;
}
```

Откуда берётся `nullptr`? Из функций, которые «не нашли» результат (`find`), из неинициализированных полей, из параметров по умолчанию. **Правило:** если функция может вернуть «ничего», она возвращает `nullptr`, и вызывающий обязан проверить.

**📝 Задание 6.1.**
Напишите функцию `void safePrint(int* p)`, которая:
- если `p == nullptr`, печатает `"null"`;
- иначе печатает `*p`.

Вызовите её дважды: с `nullptr` и с адресом реальной переменной.

**Разбор.**
```cpp
void safePrint(int* p) {
    if (p) std::cout << *p << "\n";
    else   std::cout << "null\n";
}

int main() {
    int x = 42;
    safePrint(nullptr);   // null
    safePrint(&x);        // 42
}
```
Здесь `if (p)` — сокращение для `if (p != nullptr)`. Указатель в условии неявно преобразуется в `bool`: `nullptr` → `false`, любой другой адрес → `true`.

## Часть II. Ссылки

### Шаг 7. Ссылка — второе имя для объекта

**Ссылка** — это не новый объект, а **псевдоним** уже существующего. Объявляется через `&` в типе:

```cpp
int x = 42;
int& r = x;    // r — ссылка на x
r = 100;       // то же самое, что x = 100
std::cout << x; // 100
```

Ссылка **не занимает отдельной памяти** (на уровне языка — это просто другое имя). Компилятор обычно реализует её как скрытый указатель, но для вас это невидимо.

Ключевое отличие от указателя: **ссылка не является отдельным объектом**. Это как если бы у человека было два имени — Петя и Пётр. Обращаетесь к «Пете» — обращаетесь к тому же человеку, что и «Пётр».

**📝 Задание 7.1.**
Объявите `int x = 5; int& r = x;`. Выведите `x`, `r`, `&x`, `&r`. Что совпало и почему?

**Разбор.** `x` и `r` выведут `5`. `&x` и `&r` будут **одинаковыми** — потому что `r` — это псевдоним `x`, а не отдельная переменная. Адрес у них один.

---

### Шаг 8. Три правила ссылок (и почему они такие)

**Правило 1. Ссылку нужно инициализировать сразу.**

```cpp
int& r;   // ❌ ошибка компиляции
```

Почему? Ссылка — это псевдоним **чего-то конкретного**. Нельзя создать «псевдоним ничего». В отличие от указателя, у ссылки нет состояния «пока ни на что не указывает».

**Правило 2. Ссылку нельзя переприсвоить.**

```cpp
int a = 1, b = 2;
int& r = a;
r = b;    // это НЕ перепривязка! Это a = b
```

Почему так? Потому что `r` — это буквально `a`. Присваивание `r = b` означает «присвоить `a` значение `b`». Ссылка продолжает указывать на `a`, просто `a` теперь равно `b`.

**Правило 3. Ссылка не может быть `nullptr`.**

```cpp
int& r = nullptr;   // ❌ ошибка
```

Потому что `nullptr` — это не объект `int`. Ссылка обязана ссылаться на существующий объект правильного типа.

**📝 Задание 8.1.**
Дан код:
```cpp
int a = 1, b = 2;
int& r = a;
r = b;
std::cout << a << " " << b << " " << r;
```
Что выведет? Ссылается ли `r` теперь на `b`? Объясните.

**Разбор.** Выведет `2 2 2`. `r = b` **не перепривязала** `r` к `b` — она скопировала значение `b` в `a`. `r` по-прежнему ссылается на `a`, а `a` теперь равно 2. Это классическая ловушка для тех, кто привык к указателям: у ссылок нет «перенаправления».

**📝 Задание 8.2.**
Попробуйте скомпилировать по очереди:
```cpp
int& r1;              // ?
int& r2 = nullptr;    // ?
```
Объясните каждую ошибку.

**Разбор.** `r1` — не инициализирована, а ссылка обязана сразу указывать на объект. `r2` — `nullptr` не является объектом типа `int`, поэтому ссылку на него сделать нельзя. Обе строки — ошибки компиляции (не UB, а именно ошибка на этапе компиляции, что хорошо).

### Шаг 9. `const T&` — читать без копирования

Одно из главных применений ссылок — **передача объектов в функции без копирования**. Если объект большой (например, `std::string` на тысячи символов), копировать его дорого. Ссылка позволяет работать с оригиналом.

Но если функция только **читает**, вы не хотите, чтобы она могла случайно изменить объект. Для этого есть **`const T&`**:

```cpp
void print(const std::string& s) {
    std::cout << s;
    // s = "oops";   // ❌ ошибка компиляции — нельзя менять через const-ссылку
}
```

Плюсы:
- **Нет копии** — быстро.
- **Нельзя изменить** — безопасно.
- **Можно передать временный объект** (rvalue), например литерал — `const T&` умеет «прилипать» к временным значениям и продлевать им жизнь до конца вызова.

**📝 Задание 9.1.**
Напишите `void print(const std::vector<int>& v)`, которая печатает элементы. Почему здесь `const`? Что произойдёт, если убрать `const` и вызвать `print({1, 2, 3})`?

**Разбор.** `const` нужен, чтобы функция не могла случайно испортить вектор. Если убрать `const`, вызов `print({1, 2, 3})` не скомпилируется: `{1, 2, 3}` — временный объект, а неконстантная ссылка не может привязываться к временным (иначе можно было бы изменить объект, который вот-вот умрёт — бессмысленно и опасно). `const T&` — единственный способ принять временный объект по ссылке.

## Часть III. Указатель vs ссылка — когда что

### Шаг 10. Ключевые отличия и как выбирать

| Свойство | `T*` (указатель) | `T&` (ссылка) |
|---|---|---|
| Может быть «пустым» | ✅ `nullptr` | ❌ |
| Нужна инициализация | не обязательно | обязательно |
| Можно переприсвоить | ✅ | ❌ |
| Синтаксис доступа | `p->x`, `*p` | `r.x` |
| Арифметика | ✅ (`p+1`) | ❌ |
| Занимает память | 8 байт | обычно нет |

**Правила выбора:**

- **`const T&`** — параметр функции, объект большой, менять не надо. «Всегда есть, только читаем».
- **`T&`** — параметр функции, объект надо менять. «Всегда есть, меняем».
- **`T*`** — объект **может отсутствовать** (`nullptr`), или надо «перенаправить», или массив, или хранение в контейнере разнотипных объектов.
- **`unique_ptr<T>` / `shared_ptr<T>`** — когда надо **владеть** объектом (отвечать за его удаление).

**📝 Задание 10.1.**
Для каждой ситуации выберите `T`, `T&`, `const T&`, `T*` или `unique_ptr<T>` и обоснуйте:
1. Функция печатает большой объект, не меняя его.
2. Функция ищет объект и может ничего не найти.
3. Функция должна увеличить счётчик вызывающего.
4. Класс владеет объектом и отвечает за его удаление.
5. Функция принимает маленький `int` и не меняет его.

**Разбор.**
1. `const T&` — не копируем, не меняем.
2. `T*` — возвращает `nullptr`, если не нашли.
3. `T&` — меняем оригинал.
4. `unique_ptr<T>` — единоличное владение с автоматическим удалением.
5. `T` (по значению) — копия `int` стоит копейки, ссылка тут только усложнит.

## Часть IV. Указатели, ссылки и функции

### Шаг 11. Три способа передать аргумент

```cpp
void byValue(int x)      { x = 100; }   // копия
void byPointer(int* p)   { *p = 100; }  // через адрес
void byReference(int& r) { r = 100; }   // через псевдоним
```

**По значению** — функция получает копию. Меняет копию, оригинал не трогает. Подходит для маленьких типов.

**По указателю** — функция получает адрес. Через `*p` меняет оригинал. Нужно проверять на `nullptr`, и вызов выглядит как `f(&x)` — с явным `&`.

**По ссылке** — функция получает псевдоним. Меняет оригинал напрямую. Вызов выглядит как `f(x)` — без `&`, синтаксис чище. Не может быть `nullptr`.

В современном C++ **предпочитают ссылки**, когда объект обязателен. Указатели — когда объект может отсутствовать или нужна «адресная арифметика».

**📝 Задание 11.1.**
Напишите три функции `incVal(int)`, `incPtr(int*)`, `incRef(int&)`, каждая увеличивает аргумент на 1. Вызовите все три последовательно с `int a = 5` и после каждого вызова печатайте `a`. Объясните результат.

**Разбор.**
```cpp
void incVal(int x)      { x++; }
void incPtr(int* p)     { (*p)++; }
void incRef(int& r)     { r++; }

int a = 5;
incVal(a); std::cout << a;  // 5 — копия
incPtr(&a); std::cout << a; // 6 — через адрес
incRef(a); std::cout << a;  // 7 — через ссылку
```
Первая не меняет `a`, потому что работает с копией. Вторая и третья меняют оригинал. Разница между второй и третьей — только в синтаксисе (`&a` и `(*p)++` против `a` и `r++`).

**📝 Задание 11.2.**
Напишите `void swapPtr(int* a, int* b)` и `void swapRef(int& a, int& b)`, обе меняют значения местами. Проверьте на `int x = 1, y = 2;`.

**Разбор.**
```cpp
void swapPtr(int* a, int* b) { int t = *a; *a = *b; *b = t; }
void swapRef(int& a, int& b) { int t = a;  a = b;  b = t;  }
```
Обе работают. Версия со ссылками читается проще (не нужны звёздочки), поэтому в C++ предпочитают её.

### Шаг 12. Возврат указателя и ссылки из функции

Функция может вернуть **ссылку** — тогда результат можно менять на месте. Может вернуть **указатель** — тогда вызывающий должен проверить на `nullptr`.

```cpp
int& at(std::vector<int>& v, size_t i) { return v[i]; }   // ссылка
int* find(std::vector<int>& v, int t)  { /* ... */ return nullptr; } // указатель
```

Но есть **критическое правило**: **никогда не возвращайте ссылку или указатель на локальную переменную**.

```cpp
int& bad() {
    int x = 5;
    return x;   // ❌ x уничтожится при выходе, ссылка «висит»
}
```

Почему? Локальные переменные живут на стеке и уничтожаются, когда функция завершается. Ссылка/указатель на них указывает в «мёртвую» память — это UB. Программа может «случайно работать», но это чистая случайность, и в любой момент может сломаться.

**📝 Задание 12.1.**
Напишите `int& at(std::vector<int>& v, size_t i)`. Проверьте:
```cpp
std::vector<int> v = {1, 2, 3};
at(v, 1) = 100;   // v должно стать {1, 100, 3}
```
Почему здесь возвращать ссылку **безопасно** (в отличие от `bad()`)?

**Разбор.** `v` — параметр-ссылка, ссылается на вектор вызывающего, который живёт после возврата из `at`. Значит, `v[i]` — элемент внешнего вектора, он никуда не исчезает. В `bad()` переменная `x` — локальная, умирает при выходе. Разница: **время жизни** того, на что ссылаемся.

**📝 Задание 12.2.**
Объясните, почему это UB, и предложите два способа исправить:
```cpp
int& bad() { int x = 5; return x; }
```

**Разбор.** `x` живёт только внутри `bad()`. При выходе стек-фрейм разрушается, память под `x` освобождается. Ссылка указывает в неё — UB.
Способы:
1. Вернуть по значению: `int bad() { return 5; }` — копия, безопасно.
2. Выделить в куче и вернуть `unique_ptr<int>`: `return std::make_unique<int>(5);` — живёт, пока владелец не удалит.

## Часть V. Куча: `new` / `delete` и умные указатели

### Шаг 13. Стек и куча

**Стек** — быстрая автоматическая память. Локальные переменные живут, пока выполняется блок; при выходе автоматически уничтожаются.

**Куча (heap)** — «долгоживущая» память. Объект живёт, пока вы его не удалите явно. Это нужно, когда объект должен пережить функцию, в которой создан.

```cpp
void f() {
    int a = 5;              // стек: умрёт при выходе
    int* p = new int(5);    // куча: живёт, пока не delete p
    delete p;               // освободили
}
```

`new T(...)` выделяет память в куче, конструирует объект и возвращает указатель. `delete p` вызывает деструктор и освобождает память. Забыли `delete` — **утечка памяти** (память занята, но недоступна).

**📝 Задание 13.1.**
Выделите `int` в куче через `new`, присвойте `42`, выведите через `*p`, затем `delete`. Скомпилируйте с `-fsanitize=address` и убедитесь, что утечек нет. Затем **уберите** `delete` и запустите снова — что скажет ASan?

**Разбор.** Без `delete` ASan сообщит об утечке (`LeakSanitizer: detected memory leaks`) и покажет, где именно выделялась память. Это ровно та ошибка, от которой спасают умные указатели.

---

### Шаг 14. Умные указатели — современный способ

Ручной `new`/`delete` — источник большинства багов в C++. В современном C++ используют **умные указатели** из `<memory>`:

```cpp
#include <memory>

auto p = std::make_unique<int>(42);   // unique_ptr<int>
auto s = std::make_shared<int>(42);   // shared_ptr<int>
// delete не нужен — освободится автоматически
```

- **`unique_ptr`** — единоличный владелец. Копировать нельзя, перемещать (`std::move`) можно. Освобождает объект, когда сам уничтожается.
- **`shared_ptr`** — несколько владельцев. Ведёт счётчик ссылок; когда он доходит до 0, объект освобождается.

Умные указатели **ведут себя как указатели** (`*p`, `p->x` работают), но при этом автоматически освобождают память. Это классический пример **RAII**: ресурс живёт, пока жив объект-владелец.

**📝 Задание 14.1.**
Перепишите задание 13.1 через `std::make_unique<int>(42)`. Убедитесь, что `delete` не нужен и ASan молчит.

**📝 Задание 14.2.**
Объясните разницу: что будет, если попытаться скопировать `unique_ptr`? А `shared_ptr`?

**Разбор.** `unique_ptr` копировать нельзя (ошибка компиляции) — иначе было бы два владельца одного объекта, и кто-то удалил бы его первым. Можно только `std::move` (передача владения). `shared_ptr` копировать можно — счётчик ссылок увеличивается, объект удалится, когда счётчик обнулится.

## Часть VI. Указатели и массивы

### Шаг 15. Имя массива — указатель на первый элемент

```cpp
int arr[3] = {10, 20, 30};
int* p = arr;           // то же, что &arr[0]
std::cout << *p;        // 10
std::cout << *(p + 1);  // 20
std::cout << p[2];      // 30
```

`p[i]` — синтаксический сахар для `*(p + i)`. Арифметика указателей сдвигает на `sizeof(T)` байт, а не на 1: `p + 1` для `int*` сдвигает на 4 байта.

**📝 Задание 15.1.**
Дан `int arr[5] = {1, 2, 3, 4, 5};`. Через указатель `p = arr` выведите все элементы, используя `*(p + i)` в цикле. Сравните с выводом через `arr[i]` — совпадает?

**Разбор.** Оба способа дают одно и то же. `arr[i]` компилятор всё равно переводит в `*(arr + i)`. Синтаксис с `[]` просто удобнее для чтения.

**📝 Задание 15.2.**
Выведите `sizeof(arr)` и `sizeof(p)` (где `p = arr`). Почему они разные?

**Разбор.** `sizeof(arr)` = 5 × 4 = 20 — компилятор знает размер массива. `sizeof(p)` = 8 — это размер указателя. Имя массива в выражении «затухает» до указателя на первый элемент, но `sizeof` — исключение: для самого массива он даёт размер всего массива.

---

### Шаг 16. Массив «теряет размер» при передаче в функцию

```cpp
void f(int arr[]) {            // это НЕ массив, а int*!
    std::cout << sizeof(arr);  // 8, а не 20
}
```

Когда массив передаётся в функцию, он **затухает** до указателя на первый элемент. Функция не знает, сколько элементов в массиве. Это классический источник ошибок: `for (int i = 0; i < n; i++)` с неправильным `n` — выход за границы.

**📝 Задание 16.1.**
Напишите функцию, принимающую массив по указателю, и убедитесь, что `sizeof` внутри даёт 8. Как передать «массив с размером»? Назовите два способа.

**Разбор.** Способы:
1. Передать `size_t n` отдельным параметром: `void f(int* arr, size_t n)`.
2. Использовать `std::vector<int>`, `std::array<int, N>` или `std::span<int>` (C++20) — они знают свой размер.

## Часть VII. `const` и указатели

### Шаг 17. Три разных `const`

Это самая путаная тема для новичков, потому что `const` может относиться к **указателю** или к **объекту, на который он указывает**, — и это разные вещи.

```cpp
int x = 1, y = 2;

const int* p1 = &x;         // указатель на const int
int* const p2 = &x;         // const указатель на int
const int* const p3 = &x;   // const указатель на const int
```

**Мнемоника:** читайте **справа налево** от имени переменной.
- `p1` — «p1 is a pointer to const int» → указатель на константный int.
- `p2` — «p2 is a const pointer to int» → константный указатель на int.
- `p3` — «p3 is a const pointer to const int» → константный указатель на константный int.

Что можно, а что нельзя:

| | `*p = 30` | `p = &y` |
|---|---|---|
| `const int* p1` | ❌ | ✅ |
| `int* const p2` | ✅ | ❌ |
| `const int* const p3` | ❌ | ❌ |

**📝 Задание 17.1.**
Для `p1`, `p2`, `p3` проверьте компилятором каждую из четырёх попыток (менять `*p`, менять `p`). Запишите, какие компилируются, какие нет.

**Разбор.** `p1`: `*p1 = 30` — ошибка, `p1 = &y` — ok. `p2`: `*p2 = 30` — ok, `p2 = &y` — ошибка. `p3`: обе — ошибка.

**📝 Задание 17.2.**
Как объявить «константный указатель на константный `int`»? А «указатель на константный `int`»? Запишите обе формы и объясните разницу.

**Разбор.** `const int* const p = &x;` — и указатель, и объект константны. `const int* p = &x;` — только объект. Разница: в первом случае нельзя перенаправить `p` на другой адрес, во втором — можно.

### Шаг 18. `const`-ссылки

```cpp
int& r = x;             // обычная ссылка — можно менять x через r
const int& cr = x;      // ссылка на const int — нельзя менять x через cr
```

`int& const` **не существует** — ссылка и так не переприсваивается, поэтому `const` к ней не приписывается. А вот `const int&` — осмысленно: ссылка на объект, который нельзя менять через неё.

**📝 Задание 18.1.**
Объясните, почему `int& const r = x;` не компилируется, а `const int& r = x;` компилируется.

**Разбор.** У ссылки нет «самой себя» для константности — она не отдельный объект, поэтому `const` после `&` бессмысленен и запрещён. А `const int&` — это «ссылка на const int», то есть вы не можете менять объект через эту ссылку. Это осмысленное и частое.

## Часть VIII. Опасности

### Шаг 19. Висячие указатели и ссылки (dangling)

Две классические ситуации:

```cpp
int* bad() { int x = 5; return &x; }        // x умрёт — указатель «висит»
int* p = new int(5); delete p; *p = 10;     // use-after-free
```

В обоих случаях указатель/ссылка указывает в память, которая больше не принадлежит объекту. Это **UB**: может «сработать», может упасть, может испортить другие данные.

**📝 Задание 19.1.**
Объясните обе ситуации. Как исправить каждую?

**Разбор.** 1) Вернуть по значению (`int bad() { return 5; }`) или выделить через `unique_ptr` — тогда объект живёт, пока владелец не удалит. 2) После `delete` поставить `p = nullptr` (тогда разыменование упадёт сразу и предсказуемо), или вообще не использовать сырой `new`/`delete` — взять `unique_ptr`, который сам удалит.

---

### Шаг 20. Двойное удаление и утечки

```cpp
int* p = new int(5);
delete p;
delete p;            // ❌ UB — двойное освобождение
```

```cpp
void f() { int* p = new int(5); }   // ❌ утечка — нет delete
```

Обе ошибки исчезают при использовании `unique_ptr`.

**📝 Задание 20.1.**
Напишите маленькую программу с утечкой (забытый `delete`), запустите с `-fsanitize=address,leak`, прочитайте отчёт ASan. Исправьте — сначала вручную через `delete`, потом через `unique_ptr`.

**Разбор.** ASan покажет стек, где выделялась память, и подтвердит утечку. С `unique_ptr` отчёт будет чистым, потому что деструктор умного указателя вызывает `delete` автоматически.

### Шаг 21. Разыменование `nullptr`

```cpp
int* p = nullptr;
*p = 5;   // ❌ segfault / UB
```

Самая частая ошибка новичков — забыть проверить указатель, пришедший из функции или из поля класса.

**📝 Задание 21.1.**
Напишите `void setFive(int* p)`: если `p == nullptr`, ничего не делает; иначе `*p = 5`. Вызовите с `nullptr` — не должно падать.

**Разбор.**
```cpp
void setFive(int* p) {
    if (p) *p = 5;
}
```
Без проверки вызов `setFive(nullptr)` упал бы с segfault.
