## Блок 1. Зачем нужно наследование

Представь, что ты пишешь программу про животных. У тебя есть классы `Dog`, `Cat`, `Cow`. У всех есть **общее**: имя, возраст, метод `eat()`, метод `sleep()`. И **разное**: `Dog::bark()`, `Cat::meow()`, `Cow::moo()`.

Если писать каждый класс с нуля — придётся **три раза** копировать одно и то же. А если захочешь поменять `eat()` — править в трёх местах. Рано или поздно где-то забудешь — и программы начнут вести себя по-разному.

**Наследование** решает эту проблему: **общее выносим в одного «родителя», разное оставляем в «детях»**.

```cpp
// ─── РОДИТЕЛЬ: только то, что есть у ВСЕХ животных ───
class Animal {
public:
    std::string name;   // есть у любого животного
    int age;            // тоже у любого

    void eat() {        // любое животное умеет есть
        std::cout << name << " ест\n";
    }
    void sleep() {      // и спать
        std::cout << name << " спит\n";
    }
};

// ─── РЕБЁНОК: Dog ───
// ": public Animal" читается как "Dog является Animal"
// Всё, что было в Animal (name, age, eat, sleep), автоматически
// появляется в Dog — писать это ещё раз НЕ нужно.
class Dog : public Animal {
public:
    // Внутри Dog доступны name, age, eat(), sleep() — они пришли от Animal.
    // А здесь мы добавляем то, что есть ТОЛЬКО у собак:
    void bark() {
        std::cout << name << " гавкает\n";   // name — унаследованное поле
    }
};

int main() {
    Dog d;                  // создаём собаку
    d.name = "Шарик";       // поле из Animal — работает
    d.age = 3;              // тоже из Animal
    d.eat();                // метод из Animal — напечатает "Шарик ест"
    d.bark();               // метод из Dog    — напечатает "Шарик гавкает"
}
```

Смотри, что мы **не писали** в `Dog`: ни `name`, ни `age`, ни `eat()`, ни `sleep()`. Всё это пришло от `Animal` автоматически.

**Термины на будущее:**
- `Animal` — **базовый класс** (родитель, base).
- `Dog` — **производный класс** (наследник, ребёнок, derived).
- `: public Animal` — **способ наследования**. В 95% случаев нужен именно `public`, пока просто запомни: **пиши `public` и не думай**.

## Блок 2. Что именно наследуется, а что — нет

Наследуется **всё, что есть у родителя**, но не всё доступно напрямую.

Разберём, как класс устроен «внутри»:

```cpp
class Animal {
private:
    int secret = 42;
    // ↑ private: доступно ТОЛЬКО внутри Animal.
    //   Даже наследник Dog не увидит это поле.
    //   Так прячут внутренние детали, чтобы дети не сломали.

protected:
    int age = 0;
    // ↑ protected: доступно Animal И его наследникам (Dog, Cat...),
    //   но НЕ доступно коду снаружи (из main).
    //   Это "семейная тайна": свои знают, чужие — нет.

public:
    std::string name;
    // ↑ public: доступно всем, включая main.
    //   Это "витрина" — то, что класс показывает миру.
};
```

Шпаргалка:

| Модификатор | Кто может обращаться |
|---|---|
| `public` | все (включая код снаружи) |
| `protected` | сам класс **и его наследники** |
| `private` | **только** сам класс (наследники — нет!) |

`protected` придуман **именно для наследования**: «спрятано от чужих, но открыто детям». Если ты хочешь, чтобы наследник мог работать с полем — делай его `protected`, а не `private`.

**Ещё один момент:** конструкторы и деструкторы **не наследуются**. Каждый класс пишет свои. Об этом — блок 3.

## Блок 3. Порядок вызова конструкторов и деструкторов (важно!)

Когда создаётся объект наследника, **сначала вызывается конструктор родителя**, потом ребёнка. При уничтожении — **строго наоборот**.

Почему так? Логично: нельзя строить второй этаж, пока нет первого. Родитель готовит «фундамент», ребёнок кладёт своё сверху. Сносим наоборот — сверху вниз.

```cpp
class Animal {
public:
    Animal() {
        // Этот код сработает ПЕРВЫМ при создании Dog.
        // Animal должен подготовить "фундамент" (name, age)
        // до того, как Dog начнёт что-то делать со своими полями.
        std::cout << "Animal создан\n";
    }
    ~Animal() {
        // При уничтожении Dog этот код сработает ПОСЛЕДНИМ —
        // сначала уберётся "второй этаж" (Dog), потом "фундамент" (Animal).
        std::cout << "Animal удалён\n";
    }
};

class Dog : public Animal {
public:
    Dog() {
        // Сработает ВТОРЫМ — после Animal().
        // Компилятор сам, без нашего участия, вызывает Animal()
        // перед тем, как войти в тело Dog().
        std::cout << "Dog создан\n";
    }
    ~Dog() {
        // Сработает ПЕРВЫМ при удалении — раньше, чем ~Animal().
        std::cout << "Dog удалён\n";
    }
};

int main() {
    Dog d;
}
```

Вывод:

```
Animal создан
Dog создан
Dog удалён
Animal удалён
```

Обрати внимание: **ничего не пришлось писать вручную**, чтобы «вызвать родительский конструктор». Компилятор сам это делает. Единственное исключение — если у родителя **нет** конструктора по умолчанию (блок 3.5).

## Блок 3.5. Если у родителя нет конструктора по умолчанию

Помнишь ловушку из прошлой темы: если у класса есть **хоть один** конструктор — конструктор по умолчанию не создаётся. То же работает и в наследовании — но с последствиями.

Если у `Animal` есть только конструктор **с параметрами**:

```cpp
class Animal {
public:
    Animal(std::string n) { name = n; }
    // У Animal НЕТ конструктора без параметров —
    // есть только этот, которому нужен аргумент.
};

class Dog : public Animal {
public:
    Dog() { }
    // ❌ Ошибка! Компилятор хочет вызвать Animal() перед телом Dog() —
    //    но такого конструктора нет. Он не знает, что передать в Animal(...).
};
```

**Решение** — сказать явно, что передать, через **список инициализации**:

```cpp
class Dog : public Animal {
public:
    Dog() : Animal("собака без имени") { }
    //     ↑ это НЕ присваивание полю. Это ВЫЗОВ конструктора родителя.
    //     Мы говорим: "прежде чем строить Dog, вызови Animal вот с таким аргументом".
    //     Только после этого выполнится тело { }.
};
```

Синтаксис `: Animal(...)` — тот же самый, что в прошлой теме `: x_(x), y_(y)`. Просто теперь там не поле класса, а **вызов конструктора родителя**.

## Блок 4. Ребёнок может добавлять и заменять методы

Наследник **добавляет** своё — мы уже видели (`bark()`). Но ещё наследник может **переопределить** метод родителя — написать свою версию с тем же именем.

```cpp
class Animal {
public:
    void eat() { std::cout << "Animal ест\n"; }
};

class Dog : public Animal {
public:
    void eat() {   // то же имя, своя версия — "переопределение" (override)
        std::cout << "Dog ест корм\n";
        // Если нужно ещё и поведение родителя —
        // вызываем его явно через Animal::eat():
        // Animal::eat();
    }
};

int main() {
    Dog d;
    d.eat();   // "Dog ест корм" — компилятор видит d типа Dog
               // и берёт "ближайшую" версию eat() — то есть из Dog.
}
```

**Пока запомни просто:** одно имя — две версии; при вызове через объект наследника берётся **версия наследника**. Что будет при вызове **через указатель на родителя** — отдельная история, это блок 5.

## Блок 5. Указатель на родителя и `virtual` (задел на будущее)

Самое интересное в наследовании — **можно обращаться с наследником как с родителем**:

```cpp
Dog d;
Animal* p = &d;
// ↑ совершенно законно: "Dog является Animal".
//   Раз я умею работать с Animal, я точно смогу и с Dog.
//   p смотрит на Dog, но "думает", что это Animal.

p->eat();
// ↑ А вот тут ЛОВУШКА.
//   Без virtual: компилятор смотрит на ТИП УКАЗАТЕЛЯ (Animal*)
//                и вызовет Animal::eat — хотя внутри реально лежит Dog!
//   С virtual:   компилятор посмотрит на РЕАЛЬНЫЙ объект (Dog)
//                и вызовет Dog::eat. Это называется полиморфизм.
```

Чтобы вызвать **настоящую** версию (по реальному типу объекта), метод надо объявить `virtual` у родителя:

```cpp
class Animal {
public:
    virtual void eat() { std::cout << "Animal ест\n"; }
    // ↑ virtual = "наследник может переопределить меня,
    //   и при вызове через Animal* берётся версия РЕАЛЬНОГО объекта"
};
```

Теперь `p->eat()` вызовет `Dog::eat`, если внутри `Dog`. Это называется **полиморфизм** — «одна команда, разное поведение в зависимости от реального объекта». На следующем занятии разберём подробно.

**Сегодня запомни одно:** если планируешь хранить наследников через указатель на родителя и ждать «правильного» поведения — метод родителя должен быть `virtual`.

## Блок 6. Виртуальный деструктор (коротко, но важно)

Если ты удаляешь наследника **через указатель на родителя**:

```cpp
Animal* p = new Dog;   // создали Dog, но храним как Animal*
delete p;
// ↑ Если ~Animal НЕ virtual:
//   вызовется ТОЛЬКО ~Animal. ~Dog — НЕ вызовется!
//   Всё, что Dog захватил (память, файлы) — утечёт.

// Если ~Animal virtual:
//   сначала вызовется ~Dog (уберёт своё),
//   потом ~Animal (уберёт общее). Правильно.
```

**Правило:** если у класса есть хотя бы один `virtual`-метод (или ты собираешься хранить наследников по указателю на родителя) — **сделай деструктор `virtual`**:

```cpp
class Animal {
public:
    virtual ~Animal() { }
    // ↑ пустое тело — ничего не делает, но гарантирует,
    //   что при delete через Animal* вызовется правильный деструктор.
};
```

Стоит это правило запомнить раз и навсегда — оно спасает от очень неприятных багов.

## Блок 7. Мини-проект

### ✏️ Задание 8

Построй небольшую иерархию:

```cpp
// ─── РОДИТЕЛЬ ───
class Shape {
public:
    std::string name = "фигура";

    // virtual — чтобы наследники могли переопределить
    // и чтобы вызов через Shape* давал "правильную" версию
    virtual double area() const { return 0; }

    // virtual ~ — ОБЯЗАТЕЛЬНО, раз есть виртуальные методы:
    // будем удалять через Shape* — без него утечка
    virtual ~Shape() { }

    // обычный метод — работает одинаково для всех фигур
    void print() const {
        std::cout << name << ": " << area() << "\n";
        //       ↑ area() здесь виртуальная — вызовется
        //         версия РЕАЛЬНОГО объекта (Circle или Rect),
        //         а не Shape::area()
    }
};

// ─── НАСЛЕДНИК 1 ───
class Circle : public Shape {
    double radius;
public:
    Circle(double r) : radius(r) { name = "круг"; }
    //                           ↑ name унаследовано от Shape
    double area() const override { return 3.14 * radius * radius; }
    //                ↑ override — необязательное слово, но полезное:
    //                  если сигнатура не совпадёт с родителем — компилятор скажет
};

// ─── НАСЛЕДНИК 2 ───
class Rect : public Shape {
    double w, h;
public:
    Rect(double w, double h) : w(w), h(h) { name = "прямоугольник"; }
    double area() const override { return w * h; }
};
```

В `main`:

1. Создай `Circle` и `Rect` на стеке. Вызови `print()` на каждом напрямую.
2. Создай вектор указателей:

```cpp

shapes.push_back(new Circle(1.0));
shapes.push_back(new Rect(2, 3));
// ↑ храним наследников как Shape* — это работает,
//   потому что "Circle является Shape"
```

3. Пройди по всем через `print()` — обрати внимание, что вызывается **разная** `area()` в зависимости от реального типа.
4. Удали все через `delete` — убедись, что виртуальный деструктор срабатывает.
