# Лабораторная работа: Инкапсуляция в C++ — `public`, `private`, `protected`

## Тема
Спецификаторы доступа `public`, `private`, `protected` и инкапсуляция в классах C++.

## Цель работы
Изучить принципы инкапсуляции, разобраться в различиях между уровнями доступа к членам класса, научиться правильно проектировать интерфейс класса и защищать внутренние данные от некорректного использования извне.

## Теоретическая справка

### Что такое инкапсуляция?

**Инкапсуляция** — это принцип ООП, при котором внутреннее устройство объекта скрыто от внешнего мира, а взаимодействие происходит через специально определённый интерфейс (набор публичных методов).

Представьте пульт от телевизора: у вас есть кнопки (публичный интерфейс), но вы не лезете внутрь корпуса с отвёрткой, чтобы переключить канал (внутреннее устройство скрыто).

### Уровни доступа членов класса

| Спецификатор | Доступ внутри класса | Доступ извне (в `main`, других классах) |
|--------------|:---:|:---:|
| `public`     | ✅ | ✅ |
| `protected`  | ✅ | ❌ |
| `private`    | ✅ | ❌ |

> **Важно:** сейчас мы рассматриваем доступ **без наследования**. Разница между `private` и `protected` проявится позже, когда вы изучите наследование. Пока считайте их почти одинаковыми «снаружи», но разными по смыслу.

### Зачем нужны `private` и `protected`?

- **`public`** — это «фасад» класса. То, что видят и используют другие программисты.
- **`private`** — внутренняя «кухня». Сюда нельзя залезть извне, чтобы не сломать логику объекта.
- **`protected`** — почти то же самое, что `private`, но предназначено для будущих наследников (изучим позже).

### Ключевое правило

> **Все поля класса делаем `private`. Доступ к ним — только через `public` методы.**

Это позволяет:
- Контролировать корректность данных (валидация в сеттерах).
- Менять внутреннюю реализацию, не ломая код, который использует класс.
- Защищать данные от случайного изменения.

## Задание 1. Знакомство с уровнями доступа

Создайте класс `Student`, описывающий студента. Поля класса разместите в разных секциях доступа, чтобы наглядно увидеть разницу.

```cpp
#include <iostream>
#include <string>

class Student {
public:
    // Публичные члены — доступны всем
    std::string name;      // ИМЯ — пусть будет публичным (для эксперимента)
    int age;               // ВОЗРАСТ — тоже публичный

private:
    // Приватные члены — доступны только внутри класса
    double averageGrade;   // средний балл
    std::string recordBook; // номер зачётки

public:
    // Публичный метод для установки среднего балла
    void setAverageGrade(double grade) {
        if (grade >= 0.0 && grade <= 5.0) {
            averageGrade = grade;
        } else {
            std::cout << "Ошибка: оценка должна быть от 0 до 5\n";
        }
    }

    double getAverageGrade() const {
        return averageGrade;
    }

    void setRecordBook(const std::string& number) {
        recordBook = number;
    }

    std::string getRecordBook() const {
        return recordBook;
    }

    void printInfo() const {
        std::cout << "Студент: " << name
                  << ", возраст: " << age
                  << ", средний балл: " << averageGrade
                  << ", зачётка: " << recordBook << "\n";
    }
};

int main() {
    Student s;

    // --- Работаем с публичными полями напрямую ---
    s.name = "Иван";
    s.age = 19;

    // --- Работаем с приватными полями через методы ---
    s.setAverageGrade(4.5);
    s.setRecordBook("AB-1234");

    s.printInfo();

    // --- Попробуйте раскомментировать строки ниже по очереди ---
    // и посмотрите, что скажет компилятор.

    // s.averageGrade = 5.0;      // Ошибка: private
    // s.recordBook = "XX-0000";  // Ошибка: private

    return 0;
}
```

2. Раскомментируйте по очереди закомментированные строки, зафиксируйте **текст ошибки компилятора**.

## Задание 3. Геттеры и сеттеры «в дикой природе»

**Требования:**

- Конструктор с параметрами.

## Задание 4. Класс с защищённым состоянием — «Счётчик» (по желанию)

Создайте класс `SafeCounter`, который:
- Хранит **приватное** целое поле `value` (начинается с 0).
- Имеет **приватное** поле `maxValue` — максимально допустимое значение (например, 100).
- Публичные методы:
  - `increment()` — увеличивает на 1, но не более `maxValue`.
  - `decrement()` — уменьшает на 1, но не ниже 0.
  - `reset()` — сбрасывает в 0.
  - `getValue() const`.

**Проверьте работу:**

```cpp
int main() {
    SafeCounter c;
    for (int i = 0; i < 105; ++i) c.increment();
    std::cout << "После 105 инкрементов: " << c.getValue() << "\n";  // 100

    for (int i = 0; i < 110; ++i) c.decrement();
    std::cout << "После 110 декрементов: " << c.getValue() << "\n";  // 0
    return 0;
}
```

## Задание 5. Заглядываем внутрь — `friend` (бонус, по желанию)

Иногда нужно дать доступ к `private`-данным не всем, а одному конкретному классу или функции. Для этого в C++ есть ключевое слово `friend`.

```cpp
class Student {
private:
    double averageGrade;
    std::string recordBook;

    // Объявляем класс Deanery дружественным
    friend class Deanery;

public:
    Student(double g, const std::string& r) : averageGrade(g), recordBook(r) {}
};

class Deanery {
public:
    void inspect(const Student& s) {
        // Есть доступ к приватным полям!
        std::cout << "Зачётка: " << s.recordBook
                  << ", балл: " << s.averageGrade << "\n";
    }
};

int main() {
    Student s(4.5, "AB-1234");
    Deanery d;
    d.inspect(s);   // Работает, потому что Deanery — friend
    // s.averageGrade; // А здесь — по-прежнему ошибка
    return 0;
}
```

## Методические указания

- Каждое задание — отдельный файл или отдельная функция в `main`.
- **Правило хорошего тона:** поля класса — `private`, доступ — через публичные методы.
- Сеттеры проверяют входные данные, геттеры — возвращают значения, не изменяя объект (ставьте `const` после имени метода).
