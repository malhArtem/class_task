## Блок 2. Изменение элементов, `push` / `pop` / `shift` / `unshift`

**Теория (кратко).** `push` добавляет в **конец**, `pop` удаляет **с конца**. `unshift` добавляет в **начало**, `shift` удаляет **с начала**. `push`/`unshift` возвращают новую **длину**, `pop`/`shift` — **удалённый элемент**.

**Задание 2.1.** Создай пустой массив `const stack = []`. Добавь в него последовательно три элемента через `push`: `"a"`, `"b"`, `"c"`. Выведи массив. Проверь в консоли, что порядок именно такой: `["a", "b", "c"]`.

**Задание 2.2.** Продолжая работу с `stack` из предыдущего задания, удали последний элемент через `pop`. **Сохрани возвращённое значение в переменную** и выведи её отдельно (`Удалено: c`), а затем выведи сам массив. Объясни, чем `pop()` отличается от `pop` без скобок.

**Задание 2.3.** Создай `const queue = [10, 20, 30]`. Сделай два действия по порядку:
- добавь `5` в **начало** через `unshift`;
- удали первый элемент через `shift`, сохрани его в переменную и выведи.

После этого выведи итоговый массив. Ожидаемый результат: `[10, 20, 30]` (то есть вернулись к исходному состоянию — почему?).

**Задание 2.4.** Создай `const nums = [1, 2, 3]`. Поменяй значение второго элемента (с индексом `1`) на `20`, не используя методы массива — только обращение по индексу. Выведи массив. Ожидаемый результат: `[1, 20, 3]`.

**Задание 2.5 (найди ошибку).** Дан код:
```js

console.log(result);
```
Студент ожидал увидеть `[1, 2, 3, 4]`, а увидел `4`. Объясни, **что возвращает** `push`, и напиши две строки: одну — чтобы вывести сам массив, вторую — чтобы вывести длину после добавления.

## Блок 3. Обход массива: `for` и `forEach`

**Теория (кратко).** `for (let i = 0; i < arr.length; i++)` — обход с индексом. `arr.forEach((el, i) => { ... })` — то же самое, но без ручного счётчика; `forEach` **ничего не возвращает**.

**Задание 3.1.** Создай `const nums = [3, 6, 9]`. Пройдись по массиву обычным `for` и выведи каждый элемент в консоль с подписью `Элемент: 3` и т.д.

**Задание 3.2.** Тот же массив и тот же вывод — но теперь через `forEach`. Сравни два варианта и напиши в комментарии одну строку: какой способ тебе кажется понятнее и почему.

**Задание 3.3.** Создай `const names = ["Аня", "Боря", "Вера"]`. Через `forEach` выведи нумерованный список:
```
1. Аня
2. Боря
3. Вера
```
Подсказка: второй параметр колбэка — индекс, а индексы начинаются с `0`, поэтому к нему нужно прибавить `1`.

**Задание 3.4.** Создай `const nums = [1, 2, 3, 4]`. Через `forEach` выведи каждое число, умноженное на `10`. В консоли должно быть `10, 20, 30, 40` — каждое на своей строке.

**Задание 3.5 (найди ошибку).** Дан код:

Студент ожидал массив `[2, 4, 6]`, а получил `undefined`. Объясни, **почему** `forEach` не подходит для этой задачи, и напиши правильный вариант — какой метод вернёт новый массив.

## Блок 4. `map` и `filter`

**Теория (кратко).** `map` возвращает **новый** массив той же длины, где каждый элемент **преобразован**. `filter` возвращает **новый** массив только из тех элементов, для которых колбэк вернул `true`. Исходный массив оба метода **не меняют**.

**Задание 4.1.** Дан массив `const nums = [1, 2, 3, 4, 5]`. Через `map` получи новый массив, в котором каждое число возведено в квадрат. Сохрани результат в переменную `squares` и выведи её. Ожидаемо: `[1, 4, 9, 16, 25]`. Дополнительно выведи исходный `nums` — убедись, что он не изменился.

**Задание 4.2.** Дан массив `const scores = [10, 15, 20, 25, 30]`. Через `filter` получи новый массив, в котором остались только значения `>= 20`. Сохрани в `passed` и выведи. Ожидаемо: `[20, 25, 30]`. В комментарии одной строкой объясни, почему `filter` для этой задачи удобнее, чем `forEach`.

**Задание 4.3.** Дан массив слов `const words = ["яблоко", "банан", "абрикос", "апельсин", "груша"]`. Через `filter` оставь только те, что начинаются с буквы `"а"`. Подсказка: у строки есть метод `startsWith("а")`. Сохрани результат и выведи — ожидаемо: `["абрикос", "апельсин"]`.

**Задание 4.4.** Дан массив `const nums = [1, 2, 3, 4, 5, 6]`. Сначала через `filter` оставь только чётные числа (`n % 2 === 0`), потом через `map` умножь каждое на `100`. Сохрани итог в `result` и выведи. Ожидаемо: `[200, 400, 600]`. Постарайся записать это **одной цепочкой**: `nums.filter(...).map(...)`.

**Задание 4.5 (найди ошибку).** Дан код:
```js
const arr = [1, 2, 3];
const doubled = arr.map(n => { n * 2 });
console.log(doubled);
```
В консоли `[undefined, undefined, undefined]`, а не `[2, 4, 6]`. Объясни причину и напиши **два** правильных варианта: с `{ }` + `return` и без фигурных скобок.

## Блок 5. `includes`, `indexOf`, `join`

**Теория (кратко).** `includes(x)` → `true` / `false`. `indexOf(x)` → индекс первого вхождения или `-1`, если элемента нет. `join(sep)` → строка из элементов, склеенных через `sep`.

**Задание 5.1.** Создай `const colors = ["red", "green", "blue"]`. Через `includes` проверь наличие `"green"` и `"pink"`. Выведи оба результата с подписями (`"green есть: true"` и т.д.). Объясни в комментарии, что именно возвращает `includes`.

**Задание 5.2.** На том же `colors` через `indexOf` найди индекс `"blue"` и `"pink"`. Выведи оба. Для `"pink"` объясни, почему вернулось именно такое число и как это значение используют в проверках (`if (idx !== -1)`).

**Задание 5.3.** Собери `colors` в одну строку через `join` **дважды**: с разделителем `", "` и с разделителем `" | "`. Выведи оба результата. Чем результат отличается от самого массива в консоли?

**Задание 5.4.** Создай `const nums = [1, 2, 3]`. Собери его через `join("")` — получишь `"123"`. Затем собери через `join("-")` — получишь `"1-2-3"`. Выведи оба варианта и проверь в консоли типы через `typeof`: почему результат `join` — строка, а не массив?

**Задание 5.5 (найди ошибку).** Дан код:
```js

console.log(arr.includes(2));   // true
```

Вторая строка выдаёт ошибку `contains is not a function`. Объясни, почему `contains` в JS нет (хотя оно есть в других языках) и какой метод надо использовать вместо него.

## Блок 9. Мини-проект «Список дел»

**Теория (кратко).** Паттерн **«массив — источник правды, страница — отражение»**: состояние (список задач) живёт в массиве в JS. Когда массив меняется — **перерисовываем** весь список заново: очищаем `<ul>` и заново создаём `<li>`. Такой подход гораздо надёжнее, чем пытаться менять отдельные DOM-элементы.

**Задание 9.1. Базовый список дел с добавлением.**
Сделай страницу с полем ввода `<input id="in">`, кнопкой `<button id="add">Добавить</button>` и пустым `<ul id="list">`.

В JS:
- объяви `let tasks = [];` — массив как **источник данных**;
- напиши функцию `render()`, которая: очищает `<ul>` (`list.innerHTML = ""`), затем через `forEach` создаёт `<li>` для каждой задачи и добавляет их в `<ul>`;
- повесь обработчик на кнопку: прочитать `.value` поля, отбросить пустые, `push` в `tasks`, вызвать `render()`, очистить поле;
- в самом конце вызови `render()` один раз — чтобы на пустом массиве всё корректно отрисовалось (ничего не должно быть).

Проверь: добавь 3 задачи, они должны появляться по порядку. Введи пустую строку — ничего не добавляется.

**Задание 9.2. Кнопка «Очистить всё».**
Добавь рядом кнопку `<button id="clear">Очистить</button>`. По клику: `tasks = []` и вызови `render()`. Убедись, что список на странице исчез, и что после этого можно снова добавлять задачи.

**Задание 9.3. Нумерованный список.**
Измени `render()`: в `forEach` используй `(task, i)` и выводи текст в формате `1. <task>`, `2. <task>` и т.д. Проверь: после добавления новой задачи нумерация должна «съезжать» вниз правильно — это признак того, что ты рисуешь **по массиву**, а не дописываешь в DOM вручную.

**Задание 9.4. Список чисел с фильтром «только чётные».**
Сделай отдельную страницу:
- `<input type="number" id="num">`, кнопки «Добавить» и «Только чётные», `<ul id="list">`;
- в JS `let nums = [];`;
- «Добавить»: читает число (не забудь `Number`), `push` в `nums`, вызывает `render()`;
- «Только чётные»: делает `render(nums.filter(n => n % 2 === 0))` — то есть **перерисовывает по отфильтрованному массиву**, **не меняя** исходный `nums`;
- `render(arr)` — функция, которая очищает `<ul>` и отрисовывает переданный массив.

После «Только чётные» нажми «Добавить» ещё раз — исходный массив цел, значит на странице снова появятся **все** числа. Объясни в комментарии, почему это правильное поведение.
