# Управляющие конструкции в JavaScript
## Блок 1. `if` / `else` / `else if`

**Теория.**

`if` — самый базовый инструмент ветвления. В скобках — **условие**, которое JS приводит к `boolean` (по правилам truthy/falsy, помнишь?). Если результат `true` — блок в фигурных скобках выполняется. Если `false` — пропускается.

```js
if (условие) {
  // выполнится, только если условие truthy
}
```

**`else`** добавляет «второй путь»: выполнится ровно тогда, когда `if` **не** сработал. Ровно один из двух блоков выполнится всегда.

```js
if (age >= 18) {
  console.log("Взрослый");
} else {
  console.log("Ребёнок");
}
```

**`else if`** — когда путей больше двух. Это **цепочка**: JS проверяет условия **сверху вниз** и выполняет **первый подходящий** блок, дальше не идёт. Если ни одно не подошло — сработает `else` (если он есть).

```js
if (score >= 90)      console.log("A");
else if (score >= 70) console.log("B");
else if (score >= 50) console.log("C");
else                  console.log("F");
```

**Главное правило — порядок веток.** Проверки идут сверху вниз, поэтому **строгие условия ставь выше мягких**. Если написать `if (score >= 50)` раньше `if (score >= 90)`, то для `score = 95` сработает первая ветка (`95 >= 50` → true), и до `A` дело не дойдёт. Это самая частая ошибка новичков.

**Фигурные скобки.** Если в блоке **одна** строка, скобки можно опустить:

```js
if (age >= 18) console.log("Взрослый");
```

Но **не рекомендуется** — при добавлении второй строки легко забыть вернуть скобки и получить баг. Всегда пиши `{ }` — это стандарт в реальном коде.

**Составные условия.** В `if` можно использовать `&&`, `||`, `!`. Скобки для читаемости — не стесняйся:

```js
if ((a > 0 && b > 0) || isVip) { ... }
```

**Вложенный `if`** — когда второе условие имеет смысл только при первом:

```js
if (isLoggedIn) {
  if (isAdmin) {
    console.log("Панель админа");
  }
}
```

Часто это упрощают через `&&`, но не всегда: `if (isLoggedIn && isAdmin)` — то же самое, но если внутри первого `if` планируется ещё код, вложенность оправдана.

## Блок 2. Тернарный оператор `? :`

**Теория.**

Тернарный оператор — **короткая форма** `if/else` для случая, когда обе ветки **возвращают значение**, а не выполняют много действий. Синтаксис:

```
условие ? значениеЕслиTrue : значениеЕслиFalse
```

Читается как вопрос: «если условие — верни это, иначе — вон то». Обрати внимание: это **одно выражение**, у него есть **значение**, поэтому его можно присвоить переменной, передать в функцию, вставить в шаблонную строку.

```js
// Присваивание
const status = age >= 18 ? "взрослый" : "ребёнок";

// В шаблонной строке
console.log(`Ты ${age >= 18 ? "можешь" : "не можешь"} голосовать`);

// В аргументе функции
alert(score >= 60 ? "Сдал" : "Не сдал");
```

**Чем отличается от `if/else`.** `if/else` — это **инструкции** (statements): они управляют выполнением, но **не возвращают** значения. Тернарник — это **выражение** (expression): у него есть результат, его можно куда-то положить. Поэтому там, где нужно «выбрать одно из двух значений» — тернарник; где нужно «сделать одно из двух действий» (например, два разных `console.log`) — `if/else`.

**Обязательные элементы.** После `?` **и** после `:` должно быть **по значению** — обе ветки обязательны. Если написать `age >= 18 ? "взрослый"` **без `:`** — это синтаксическая ошибка (или, в некоторых контекстах, вернётся `undefined`).

**Читаемость.** Тернарник хорош в одну строку, пока он короткий. **Вложенные тернарники** (`условие1 ? a : условие2 ? b : c`) технически работают, но читать их тяжело. Если вариантов больше двух — используй `if / else if / else` (или `switch`).

**Когда не использовать.** Если в ветках нужно выполнить **действие**, а не вернуть значение, — тернарник не подходит:

```js
// ❌ так не делаем — ради побочного эффекта тернарник не нужен
age >= 18 ? console.log("Взрослый") : console.log("Ребёнок");

// ✅ так правильно
if (age >= 18) console.log("Взрослый");
else           console.log("Ребёнок");
```

## Блок 3. `switch`

**Теория.**

`switch` — это **множественное ветвление по одному значению**. Он удобен, когда сравниваешь **одну переменную** с набором **конкретных значений** (не с диапазонами!). Сравнение строгое — используется `===`, поэтому `"5"` и `5` в `switch` **не** совпадут.

```js
switch (day) {
  case "пн":
    console.log("Работаем");
    break;
  case "сб":
    console.log("Отдыхаем");
    break;
  default:
    console.log("Неизвестный день");
}
```

**Как работает.** JS берёт значение в скобках (`day`) и ищет **первый** `case`, значение которого `===` этому значению. Нашёл — начинает выполнять код **с этого места**. Если ни один не подошёл — идёт в `default` (если он есть; необязателен).

**`break` — критически важен.** Без `break` после сработавшей ветки выполнение **провалится** в следующий `case`, потом в следующий — и так до конца `switch` или до ближайшего `break`. Это называется **fallthrough**. Иногда это полезно (см. ниже), но чаще — источник багов. По умолчанию — **всегда ставь `break`** после каждой ветки.

**Намеренное проваливание.** Иногда несколько значений должны обрабатываться одинаково. Тогда их можно объединить в одну группу:

```js
switch (day) {
  case "пн":
  case "вт":
  case "ср":
  case "чт":
  case "пт":
    console.log("Рабочий день");
    break;
  case "сб":
  case "вс":
    console.log("Выходной");
    break;
  default:
    console.log("Неизвестный день");
}
```

Здесь `case "пн":` без кода сразу переходит к следующему `case` — и все рабочие дни попадают в общий блок с одним `break`. Такой вариант — норм. Случайный пропуск `break` — не норм.

**`default`.** Ставь в конец (традиция), но можно и в середину. Необязателен, но полезен — «страховка на всякий случай». Как правило, `default` **не требует** `break`, потому что после него уже нечего выполнять, но для явности иногда ставят.

**`switch` vs `if/else if`.** `switch` — **только для конкретных значений** (`===`). Для диапазонов (`>=`, `<`) — только `if/else if`. Внутри `case` можно писать выражения, но это уже извращение — если нужно условие, используй `if`.

```js
// ✅ switch уместен: сравнение с конкретными строками
switch (color) {
  case "red":    /* ... */ break;
  case "green":  /* ... */ break;
}

// ❌ switch неуместен: диапазоны
switch (true) {   // работает, но это замаскированный if/else if — плохо
  case score >= 90: /* ... */ break;
  case score >= 70: /* ... */ break;
}
```

## Блок 4. Цикл `for`

**Теория.**

Классический `for` — цикл **со счётчиком**. Синтаксис состоит из трёх частей в скобках, разделённых `;`:

```js
for (инициализация; условие; шаг) {
  // тело
}
```

**Порядок выполнения:**
1. **Инициализация** — выполняется **один раз** в начале (например, `let i = 0`).
2. **Проверка условия** — если `true` → тело; если `false` → цикл завершён.
3. **Тело** — выполняется.
4. **Шаг** — выполняется после тела (например, `i++`).
5. Возвращаемся к пункту 2.

**Части могут быть пустыми.** `for (;;)` — бесконечный цикл (используется редко, обычно с `break` внутри). Но классический вид — `for (let i = 0; i < n; i++)`.

**Область видимости `let`.** Если объявить `let i = 0` **внутри** `for`, переменная `i` видна **только внутри** цикла — снаружи её нет. Это удобно: после цикла `i` «исчезает», не мешает другим переменным. Если `i` нужна после цикла — объяви её **снаружи**:

```js
let i;
for (i = 0; i < 3; i++) {}
console.log(i);   // 3
```

**`for` для массива.** Классика — обход по индексу:

```js
for (let i = 0; i < arr.length; i++) {
  console.log(arr[i]);
}
```

Важно: `i < arr.length`, **не** `<=`. При `<=` на последнем шаге `i === arr.length`, `arr[i]` → `undefined` — классическая ошибка.

**Когда `for` лучше.** Когда **нужен индекс** (например, для `arr[i] = ...`, для нумерации `1.`), или когда обход — с шагом не 1 (`i += 2`), или в обратную сторону (`i--`). Когда индекс не нужен — `for...of` короче и читаемее.

## Блок 5. Цикл `while`

**Теория.**

`while` — цикл **«пока истинно»**. Проверка условия — **до** первой итерации: если условие изначально `false`, тело **не выполнится ни разу**.

```js
while (условие) {
  // тело
}
```

**Главное отличие от `for`.** В `for` счётчик «встроен» в синтаксис (инициализация + шаг в скобках). В `while` ты **сам** управляешь переменной:

```js
let i = 1;        // ← до цикла
while (i <= 5) {
  console.log(i);
  i++;            // ← внутри тела, иначе цикл бесконечный
}
```

**Бесконечный цикл — самая частая проблема.** Если в теле не менять переменную, от которой зависит условие, — условие всегда `true`, страница зависает. Причины: забыл `i++`; забыл обновить флаг; неправильно написал условие. Если браузер завис — **закрывай вкладку** (не закрывай браузер целиком), исправляй, обновляй страницу.

**Когда `while`, а когда `for`.** `for` — когда **известно количество итераций** (или явно видно «от `1` до `n`»). `while` — когда **не знаешь заранее**, сколько будет итераций, и условие — не счётчик, а какое-то состояние:

```js
// Например, «удваивай, пока не достигнем 1000» — сколько итераций, сразу не скажешь
let n = 1;
while (n < 1000) {
  n = n * 2;
}
```

`while` — для «пока не найдём», «пока не закончится», «пока не станет больше». `for` — для обхода по индексу и счётчиков.

**`do...while` (забегая вперёд).** Есть ещё вариант с проверкой **после** первой итерации — тело выполнится хотя бы раз:

```js
do {
  // тело
} while (условие);
```

Используется редко, но полезно помнить: `while` — 0+ итераций, `do...while` — 1+ итераций.

## Блок 6. `for...of` — обход значений

**Теория.**

`for...of` — современный способ пройти по **значениям** итерируемого объекта. Для массивов, строк и других коллекций — **самый удобный** синтаксис, когда **индекс не нужен**.

```js
for (const item of array) {
  // item — очередной элемент
}
```

**Как читается.** «Для каждого `item` **из** `array` — выполнить тело». `of` — «из». Это буквально «для каждого элемента из массива».

**Что перебирает.** `for...of` работает с массивами, строками (по символам), `Map`, `Set` и любыми объектами, у которых есть итератор. Для **обычных объектов** — **не работает** (`{}` — не итерируем, для них есть `for...in`).

**Чем лучше `for` по индексу.** Короче, нет ручного счётчика, нет риска «`i <= length` вместо `<`». Меньше кода — меньше ошибок. Когда индекс **не нужен**, `for...of` — выбор по умолчанию.

**Чем лучше `forEach`.** `forEach` — это метод массива, работает через колбэк. `for...of` — синтаксическая конструкция, **в нём работают `break` и `continue`** (в `forEach` — нет). Если нужно прервать обход — только `for...of` (или классический `for`).

**Ограничение — нет индекса.** Внутри `for...of` **нет** переменной с номером. Если нужен индекс — либо `for` с `i`, либо `arr.entries()` (продвинутый способ, пока не нужен), либо `forEach` (там индекс — второй параметр колбэка).

**Изменять элемент нельзя.** Переменная `item` — это **копия** значения. `item = item * 2` внутри цикла **не изменит** массив. Если нужно поменять — работай по индексу через `for`:

```js
for (const n of [1, 2, 3]) {
```

## Блок 7. `for...in` — обход ключей объекта

**Теория.**

`for...in` перебирает **ключи** объекта — как строки. Для обычных объектов `{ ... }` — это инструмент «обойти все свойства». Для **массивов — не используем** (для массивов есть `for...of`, а `for...in` даст **индексы как строки** — источник неожиданных багов, см. задание 7.6).

```js
const user = { name: "Аня", age: 16 };
for (const key in user) {
  console.log(key, user[key]);
}
// "name Аня"
// "age 16"
```

**`key` — это строка.** Не число, не что-то особенное — просто строка с именем свойства. Поэтому:

- `user[key]` — **правильно**: `key` — переменная, JS берёт её **значение** (`"name"`) и ищет по нему свойство.
- `user.key` — **неправильно**: точка означает буквальное имя `"key"`, а такого свойства у `user` нет → `undefined`.

Это классическая ошибка новичков. Правило: **если имя свойства лежит в переменной — только квадратные скобки**.

**Порядок обхода.** Для строковых ключей — порядок **вставки**. Для числовых (если ключ выглядит как целое число) — сначала числа по возрастанию, потом строки в порядке вставки. На практике для объектов это редко важно, но знать полезно.

**Что попадает в обход.** `for...in` идёт не только по «своим», но и по **унаследованным** свойствам (из прототипа). Для обычных «плоских» объектов из литералов `{ ... }` это неважно, но если объект «сложный» — может добавить сюрпризов. Продвинутая защита — `Object.hasOwn(obj, key)`, но на старте это не нужно.

**Когда `for...in` действительно нужен.** Практически **только для объектов**, когда нужно обойти **все** их свойства и не важно, какие именно. Если нужны конкретные свойства — обращайся по имени напрямую. Если нужен массив ключей — есть `Object.keys(obj)` (позже разберём).

## Блок 8. `break` и `continue`

**Теория.**

Оба оператора работают **внутри циклов** (`for`, `while`, `for...of`, `for...in`, `do...while`). В `forEach` их **нет** (там `return` из колбэка пропускает итерацию, а «прервать» нельзя).

**`break` — полностью прерывает цикл.** Выполнение «выпрыгивает» из цикла, и код продолжается **после** него. Всё, что было бы выполнено в оставшихся итерациях, — **не выполняется**.

```js
for (let i = 1; i <= 10; i++) {
  if (i === 5) break;
  console.log(i);   // выведет 1, 2, 3, 4 — на 5 прервётся
}
console.log("После цикла");   // выполнится — break прерывает только цикл
```

`break` — это «выйти из цикла». Он **не выходит** из функции и **не завершает** программу — только текущий цикл.

**`continue` — пропускает итерацию.** Текущая итерация **завершается сразу**, тело ниже `continue` **не выполняется**, и цикл переходит к **следующей** итерации (в `for` — выполняется шаг `i++`, потом проверка условия).

```js
for (let i = 1; i <= 5; i++) {
  if (i === 3) continue;
  console.log(i);   // 1, 2, 4, 5 — тройка пропущена
}
```

`continue` — это «пропустить эту, идти к следующей». **Цикл не прерывается.**

**Разница в одной фразе:**
- `break` — «выйти совсем».
- `continue` — «пропустить текущую, идти дальше».

**Когда что.** `break` — когда дальше искать/выполнять **нет смысла** (нашли то, что искали; ошибка). `continue` — когда нужно **отфильтровать** часть итераций, но остальные выполнить (пропустить пустые, отрицательные, чётные — что угодно).

**Вложенные циклы.** `break` и `continue` действуют на **ближайший** цикл. Если внутри цикла есть ещё цикл, и ты пишешь `break` во внутреннем — прерывается **только внутренний**, внешний продолжает работать. Прервать оба сразу можно только с метками (`label:`), но это редко нужно и плохо читается — на старте не трогаем.

**`return` — не то же самое.** `return` выходит из **функции**, а не только из цикла. Если цикл внутри функции, `return` «выпрыгнет» и из цикла, и из функции. Но `break` и `return` — разные инструменты, не путай.
